# 定时任务指南

## 概述

系统使用 APScheduler 管理后台定时任务，调度器在 Flask 应用启动时初始化（`tasks/crawl_task.py`）。

## 任务列表

| 任务 ID | 名称 | 触发时间 | 爬取内容 |
|---------|------|----------|----------|
| `daily_crawl` | 每日基金数据爬取 | 每个工作日 09:00 | 基金列表页净值快照（`data/YYYYMMDD/{tag}.csv`） |
| `weekly_crawl` | 每周基金数据爬取 | 每周一 09:30 | 同上（全量重爬） |
| `daily_cumulative_crawl` | 每日累计净值爬取 | 每个工作日 10:00 | 各基金历史累计净值（`cumulative/{tag}/{fund_name}/`） |

## 爬取数据类型

### 1. 基金列表净值（daily_crawl / weekly_crawl）

- **数据来源**：私募基金网站的基金列表页面
- **输出文件**：`data/{YYYYMMDD}/{tag}.csv`
- **字段**：基金名称、单位净值、累计净值、日增长率等
- **调用函数**：`services.crawler.runner.crawl()`

### 2. 累计净值（daily_cumulative_crawl）

- **数据来源**：进入每个基金的详情页，抓取"历史净值/分红"表格
- **输出文件**：`cumulative/{tag}/{基金名称}/{基金名称}.csv`
- **字段**：日期、单位净值、分红再投净值、累计净值、涨跌幅
- **调用函数**：`services.crawler.runner.crawl_cumulative_nav()`

## 配置说明

### 批次间隔配置

累计净值爬取批次相关参数位于 `config/crawler.py`：

```python
# 每个基金详情页之间的间隔（毫秒），建议 3000~15000
CUMULATIVE_CRAWL_INTERVAL = 15000

# 批次之间间隔（秒），每批跑完后等待这段时间再继续下一批
BATCH_WAIT_BETWEEN = 300  # 5分钟
```

### 定时标签配置

爬取哪些标签由 `config/fund.py` 中的常量控制：

```python
# 所有可用标签
ALL_TAG_KEYS = ["private", "public", "money", "exp"]

# 基金列表净值定时爬取标签
SCHEDULED_TAGS = ["private", "exp"]

# 累计净值定时爬取标签
SCHEDULED_CUMULATIVE_TAGS = ["private", "exp"]
```

如需修改定时任务覆盖的标签范围，编辑 `config/fund.py` 并重启应用。

### 定时时间配置

修改 `tasks/crawl_task.py` 中 `init_scheduler()` 函数的 `CronTrigger` 参数：

```python
# 示例：改为每天 17:00 执行
_scheduler.add_job(
    func=lambda: _run_scheduled_crawl(app),
    trigger=CronTrigger(hour=17, minute=0),
    ...
)

# 示例：改为每周五 16:00 执行
_scheduler.add_job(
    func=lambda: _run_scheduled_cumulative(app),
    trigger=CronTrigger(day_of_week="fri", hour=16, minute=0),
    ...
)
```

CronTrigger 支持的参数：

- `hour`, `minute`：小时、分钟
- `day_of_week`：星期几（`mon`, `tue`, `wed`, `thu`, `fri`, `sat`, `sun`）
- `day`：每月第几天
- `month`：月份

## 手动触发

### 通过 API 触发基金列表爬取

```bash
POST /api/crawl
Content-Type: application/json

{"tags": ["private"], "sync": false}
```

### 通过 API 触发累计净值爬取

```bash
POST /api/crawl/cumulative
Content-Type: application/json

{
    "tags": ["private", "exp"],      # 可选，默认 ["private"]
    "batch_size": 5,                  # 每批几个基金，默认 5
    "wait_between_batches": 300       # 批次间等待秒数，默认 300（5分钟）
}
```

**执行逻辑：**
1. 按基金名称字母排序，保证分批稳定
2. 每个标签各自开一个全新的浏览器，会话完全独立
3. 每个标签内自动分批循环执行，批次间等待指定时间
4. 标签之间顺序执行，private 全部完成后才执行 exp

**注意：** `batch_size=0` 表示不限制，一批跑完全部（不推荐，间隔太小易触发风控）

### 查看爬取状态

```bash
GET /api/crawl/status
```

### 查看爬取记录

```bash
GET /api/crawl/records?tag=private&page=1&per_page=10
```

## 任务状态追踪

爬取记录保存在 `data/crawl_records.csv`，可通过 `/api/crawl/records` 接口查询。

异常错误码：

| 异常类型 | 含义 |
|----------|------|
| `TagNotFoundError` | 标签不存在或未配置 |
| `CookieError` | Cookie 失效，需更新 |
| `PageLoadError` | 网络问题或页面无法访问 |
| `ElementNotFoundError` | 页面结构变化，需更新爬虫 |
| `CrawlFailedError` | 其他爬取失败 |

## 注意事项

1. **Cookie 维护**：私募网站需要登录 Cookie，请定期检查 `config/site.py` 中的 Cookie 配置是否有效
2. **任务互斥**：同一时间只能有一个爬虫任务运行，后来的请求会返回 409 冲突状态；定时任务和手动 API 也会互相检测 `is_running` 状态，避免冲突
3. **批次间间隔**：累计净值爬取每批之间默认等待 5 分钟，可通过 `wait_between_batches` 调整，建议 3-10 分钟避免平台风控
4. **分批策略**：建议按标签分别调用，每批 3-5 个基金；同一标签内分批自动递进，无需手动算批次索引
5. **节假日**：定时任务按 cron 表达式执行，建议配合服务器的系统任务或监控确保节假日不产生无效执行记录
